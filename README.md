# Магазин кроссовок — итоговый проект

Flutter Web и PocketBase. Продолжение ПР2–ПР6: те же сущности и экраны, но данные
берутся с собственного сервера PocketBase, добавлены роли, мягкое удаление,
расчёт стоимости заказа, акции и отчёт.

- Сайт: https://sedive666.github.io/itog/ (данные берёт с сервера PocketBase на Render, см. раздел «Сервер в интернете»)
- Описание сервера: [backend/README.md](backend/README.md)

## Запуск

1. Скачать `pocketbase.exe` со страницы релизов https://github.com/pocketbase/pocketbase/releases и положить в папку `backend`.
2. Запустить сервер (миграции и тестовые данные применятся сами):

```bash
cd backend
./pocketbase.exe serve
```

3. Запустить приложение:

```bash
flutter run -d chrome --web-port=5555
```

Адрес сервера по умолчанию `http://127.0.0.1:8090`; меняется параметром сборки `--dart-define=PB_URL=...`.

Учётные записи (вход по почте): `admin@shop.test` / admin123, `manager@shop.test` / manager123,
`client@shop.test` / client123. Покупатели регистрируются сами.

Проверки:

```bash
flutter analyze
dart format --set-exit-if-changed lib test
flutter test
```

## Особенность предметной области

- **Расчёт стоимости.** Цена пары × (1 − активная акция) × (1 − скидка карты: Серебряная 3 %, Золотая 5 %, Платиновая 10 %).
  Расчёт на сервере (`POST /api/orders/quote`), клиент показывает его в форме заказа. При создании заказа
  цена пересчитывается ещё раз, а остаток уменьшается; при нехватке сервер отвечает 409.
- **Акции.** Периоды акций на один кроссовок не могут пересекаться (422 в поле даты).
- **Отчёт.** Выручка, заказы по статусам, выручка по брендам (столбчатая диаграмма), позиции с малым остатком.
- **Экспорт.** Кнопка «Экспорт CSV» в каждом списке (менеджер и администратор).

## Публикация

GitHub Actions при каждом изменении ветки `main`: анализатор, форматирование, тесты, сборка, выкладка на Pages.

### Сервер в интернете (Render)

Сайт по HTTPS, поэтому и сервер должен быть по HTTPS. PocketBase размещён на бесплатном сервисе Render в
Docker-контейнере: `backend/Dockerfile` (исполняемый файл PocketBase для Linux, миграции, хуки),
`backend/start.sh` (запуск) и `render.yaml` (описание сервиса). Схема и тестовые данные создаются миграциями при старте.

1. На https://render.com войти через GitHub и выбрать `New -> Blueprint`, указать репозиторий `itog`.
2. Render создаст сервис `itog-pocketbase`; пароль суперпользователя панели `/_/` он сгенерирует сам
   (переменная `PB_SUPERUSER_PASSWORD`, в репозитории его нет), почта суперпользователя — `admin@itog.local`.
3. Если адрес сервиса отличается от `https://itog-pocketbase.onrender.com`, задать его переменной репозитория `PB_URL`
   (`Settings -> Secrets and variables -> Actions -> Variables`) и перезапустить сборку.

Особенность бесплатного тарифа: после 15 минут без запросов сервис засыпает, первое обращение занимает около минуты;
постоянного диска нет, поэтому после сна база возвращается к тестовым данным.

## Известные ограничения

- Локально `flutter build web` не работает в пути с кириллицей (компилятор шейдеров не может записать файл); в CI на Linux сборка проходит.
- Отказ правила доступа PocketBase отдаёт код 400, а не 403; клиент переводит его в «Недостаточно прав».
- Остаток уменьшается при создании заказа и не возвращается при отмене или удалении заказа.
